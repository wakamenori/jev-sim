# Jev：できることと特徴

調査日：2026年9月23日

## 1. どのようなモデルか

Jev は、TypeSafe AI が2026年9月15日に早期アクセスとして発表した、ソフトウェア内の判断を担う AI モデルです。同社はこのカテゴリを「System One Model」と呼んでいます。発表では、新しいアーキテクチャ、並列サンプラー、Reinforcement Learning for Calibrated Decisions（RLCD）という学習手法を採用したと説明しています。これらは提供元の説明であり、内部構造を独自に検証したものではありません。[公式発表](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

使う側は、判断対象の情報を `state` に、問いと回答形式を `questions` に指定します。Jev は選択肢・評価値・確率を返し、アプリケーションがそれを使って処理を分岐します。同じ入力に対する複数の問いを、1回のリクエストで独立に評価できます。複雑な判断は個別の問いに分け、重み付けや最終判断をコードで組み立てる使い方が想定されています。[Introduction](https://docs.typesafe.ai/introduction)

## 2. 基本機能

### 3種類の問い

| 種類 | 何をするか | 主な戻り値 | 用途の例 |
| --- | --- | --- | --- |
| Choice | 定義した候補から1つ選ぶ。最大255候補 | `choice`、候補ごとの `probabilities`、`confidence` | 問い合わせの担当部署、商品カテゴリ、利用ツールの選択 |
| Score | 言葉で定義した2〜10段階の基準に沿って評価する | `score`、段階ごとの `probabilities`、`confidence` | 不具合の深刻度、文章の関連度、顧客の不満の程度 |
| Noul | 指定した条件が真である確率を返す | `noul`：0〜1 | 緊急性の有無、条件への適合、候補ごとの該当判定 |

出典：[Choice](https://docs.typesafe.ai/primitives/choice)、[Score](https://docs.typesafe.ai/primitives/score)、[Noul](https://docs.typesafe.ai/primitives/noul)。

Choice は候補内での選択です。候補が入力を網羅しない場合は「その他」「該当なし」を用意します。複数のラベルが同時に当てはまり得るときは、ラベルごとの Noul などに分解します。

Score の値は、段階番号を確率で重み付けした平均です。3段階なら0〜2の間の値になり、1.4のような小数も返ります。実際の人数や金額を測った値ではなく、定義した評価尺度上の位置です。[Choice](https://docs.typesafe.ai/primitives/choice)、[Score](https://docs.typesafe.ai/primitives/score)

### 確率と confidence は別の指標

`probabilities` は各候補・段階への確率配分です。`confidence` はその分布から計算した0〜1の統計量で、分布が集中しているか、分散しているかを扱いやすくしたものです。**confidence が0.9だから正解率90%と読み替えることはできません。** Noul には独立した `confidence` フィールドはありません。

アプリケーションでは、確信度が低い判断を保留し、人や別のモデルに渡せます。ただし、しきい値は用途ごとの実データで決める必要があります。[Confidence](https://docs.typesafe.ai/confidence)

## 3. 何に使えるか

以下は公式の利用例と、その仕組みから読み取れる用途です。用途の存在と、特定の業務で十分な精度が出ることは区別します。

| 用途 | Jev が担当する判断 | 周辺のコードや別モデルが担当する処理 |
| --- | --- | --- |
| 問い合わせ分類 | 担当先、緊急性、内容の種類 | チケット移動、返信文の生成 |
| エージェントのツール選択 | 関数名と、列挙可能な引数の選択 | 関数の実行、権限確認、結果の処理 |
| 検索結果の再順位付け | 質問と候補文書の関連性 | 初期検索、並べ替え、最終回答の生成 |
| 出力の確認 | 出典が主張を支えるか、不適切な内容か | 原文取得、保留・再生成・人への引き継ぎ |
| 候補からの情報抽出 | あらかじめ抽出した値のうち、どれが該当するか | 正規表現などでの候補抽出、値の正規化 |

出典：[Choice](https://docs.typesafe.ai/primitives/choice)、[Function calling](https://docs.typesafe.ai/cookbooks/function_calling)、[Re-ranking](https://docs.typesafe.ai/cookbooks/rerank_typesafe)、[公式ドキュメント索引の各 Cookbook](https://docs.typesafe.ai/llms.txt)。

Function calling の公式例は、関数と固定候補の引数を選び、通常のコードで実行するものです。任意の自由文・数値・日付をすべて自動生成できる仕様ではありません。この例のコードは `jev-1.12` を参照しており、現行版の実測として扱うべきではありません。[Function calling](https://docs.typesafe.ai/cookbooks/function_calling)

## 4. 特徴と性能の読み方

### 多数の小さな判断をまとめて処理する

同じ `state` に複数の問いをまとめると、入力を共有したまま並列に評価できます。公式説明では、問いの追加による応答時間の増加は小さいとされています。ただし、追加する問いや選択肢は入力トークンを消費します。各回答が他の回答を参照して推論する構成ではないため、回答間の依存関係はアプリケーション側で扱います。[Introduction](https://docs.typesafe.ai/introduction)、[Choice](https://docs.typesafe.ai/primitives/choice)

### 速度とコスト

公式発表の応答時間は70〜500msです。「193.6倍高速・444.6倍安価」という比較もありますが、同社のワークフロー評価に基づき、実環境で得られる改善幅の上限寄りだと同社自身が注記しています。主な計測場所は米国西海岸であり、日本から同じ遅延になる保証はありません。[公式発表](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

現行の掲載価格は入力100万トークン当たり **0.042米ドル**、出力は無料です。例として、課金対象の入力が1リクエスト1,000トークンなら、1万リクエストで0.42米ドルという計算になります。これは単価からの試算で、実測請求額ではありません。[Models](https://docs.typesafe.ai/models)

### 出力形式の保証と判断の正しさ

提供元の「ハルシネーションがない」という表現は、定義済みの出力形式に一致するという保証と併せて読む必要があります。**形式に合う回答でも、分類や判断を間違えることはあります。** 同社の既知の弱点の文書も誤判断を認めています。[公式発表](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[既知の弱点](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

### 公開評価で確認できる範囲

| 評価 | 報告された結果 | 読む際の条件 |
| --- | --- | --- |
| 提供元のワークフロー評価 | 高速・低コストを報告 | 正解ラベルではなく、外部の高性能モデルの平均予測を参照。実業務の正解率そのものではない |
| 公式の検索再順位付け例 | Top-1が5%→18%、Top-10が38%→62% | CLERCの40クエリ、3,565文章、BM25の上位30候補を使う小規模例。掲載コードは `jev-1.12` |
| 交通事故記述を構造化する研究 | 人手ラベルに対してF1 0.908 | 2026年9月21日公開のarXivプレプリント。本文の再現検証は未実施 |

出典：[公式発表・評価方法](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[Re-ranking](https://docs.typesafe.ai/cookbooks/rerank_typesafe)、[研究の要旨](https://arxiv.org/abs/2609.24052)。

交通事故の研究要旨は、2,416件の人手判断で監査し、確率校正の品質はモデルごとに異なると報告しています。これは「意思決定専用モデルなら、どの用途でも確率が正確」という解釈を支持しません。英語の特定領域の結果を、日本語業務の精度に転用することもできません。

## 5. 制約・苦手なこと

### 出力・入力の範囲

Jev 1.13 は自由な文章生成用に学習されていません。文章執筆、要約文の作成、コード生成、判断理由の説明が必要な場合は、生成モデルなどを別途使います。[既知の弱点](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

入力はテキストのみです。画像・音声・動画は事前に文字情報などへ変換する必要があります。英語が主な学習言語で、CJKを含む他言語は扱えるものの、英語と同等の精度とはされていません。[Models](https://docs.typesafe.ai/models)

### 判断の失敗要因

- **数値の厳密さ**：計数、計算、日時の順序・差分に弱い。計算はコードに任せる。
- **問いの複雑さ**：二重否定、間接的な参照、矛盾した指示で精度が落ちる。判断を分解し、条件を明記する。
- **不要な入力**：関係ない情報で `state` が長くなると精度が落ちる。必要な情報を先に抽出する。
- **敵対的な入力**：入力中の誘導や注入された指示で判断が動くことがある。型の保証は、プロンプトインジェクションへの耐性の保証ではない。
- **別々の問いの整合性**：肯定と否定を個別に問うと、確率の合計が1にならない場合がある。必要な数理的整合性はコードで保つ。

いずれも提供元が公開する Jev 1.13 の既知の弱点です。同じ `state` に問いを増やすことと、無関係な内容で `state` 自体を長くすることは分けて考える必要があります。[既知の弱点](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

## 6. 現行仕様と利用方法

| 項目 | 調査日時点の公式記載 |
| --- | --- |
| モデルID | `jev-1.13.0` |
| エイリアス | `jev-latest`、`jev-preview`。現在はどちらも同版 |
| コンテキスト | 全体64kトークン。別途、`state`＋最長の問いが32k以内 |
| レート制限 | 毎秒250,000トークン、毎分1,200リクエスト。動的に変更される |
| 顧客ごとの追加学習 | Fine-tuning / LoRAは提供せず、入力や評価基準で調整 |
| データの学習利用 | 顧客のリクエスト・レスポンスは学習に使用しないとの記載 |

出典：[Models](https://docs.typesafe.ai/models)。データを学習に使わないことと、データを保存しないことは別です。保存条件は契約・ポリシーで別途確認が必要です。

試用は [Playground](https://console.typesafe.ai) から行い、プログラムからは API キーを取得して `POST https://api.typesafe.ai/v1/systemone` を呼び出します。公式SDKとしてPythonとJavaScriptが案内されています。[Quick start](https://docs.typesafe.ai/introduction/quickstart)、[SDK](https://docs.typesafe.ai/sdk)

リクエストは `state`、`model`、`questions` を指定します。レスポンスの `answers` は問いのキーに対応しますが、**問いのキー名自体はモデルに渡りません**。判断に必要な意味は `instructions` や `criteria` に書きます。[API reference](https://docs.typesafe.ai/api)

実評価ではモデルIDを固定し、正解ラベル付きの日本語データで、精度・保留率・誤判定の種類・遅延・費用を測るのが妥当です。これは本調査からの提案であり、本リポジトリで評価を実施した結果ではありません。

## 7. 調査で未確認の点

今回確認した資料だけでは、パラメータ数、詳細なネットワーク構成、学習データの内訳、重み公開やセルフホストの提供条件は確定できません。また、日本語の独立ベンチマーク、日本からの応答時間、当該アカウントでのアクセス可否は未確認です。

現時点では、**候補や尺度を定義できる判断処理に適用するモデル**と捉えるのが適切です。導入価値は、文章生成まで任せられるかではなく、既存処理のどの判断を分離できるか、その判断を必要な精度と遅延で返せるかで評価できます。
