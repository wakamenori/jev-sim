# 構造と処理順

## 責務

| ファイル | 責務 |
| --- | --- |
| `src/cast.ts` / `constants.ts` | シナリオとターン数の定義 |
| `types.ts` / `world.ts` | 状態の型、世界の初期化、日の開始とスナップショット |
| `rules.ts` / `perception.ts` | 知識、陣営、証拠の利用、支持、暴露、脅しの状態、目撃・推測 |
| `actions.ts` | 行動の形式、読み書き、現在選べる行動 |
| `describe.ts` | 人物視点の説明文と行動の説明文 |
| `decision.ts` | モデルの分布から行動と支持を決める |
| `planning.ts` | 陣営計画と個人の整理で使う共通の行動スキーマ、指示できない行動の判定 |
| `strategy.ts` / `review.ts` | 陣営の計画、個人の整理と報告 |
| `reactions/` | 情報伝達・説得、脅し・命令、証拠の移動・処分に対する反応 |
| `engine.ts` | ターンの判断収集と結果の適用、日末の王の評価、最終指名 |
| `simulation.ts` | 計画から日末までの順序 |
| `evaluation.ts` / `generation.ts` | 意思決定の入出力契約 |
| `jev.ts` / `llm.ts` / `model-cache.ts` | モデル接続、キャッシュ、統計、Jevの同時実行制限と再試行 |
| `model-events.ts` / `run-log.ts` | 問い合わせの観測、エラー情報の抽出、実行ログと現在状況の保存 |
| `run.ts` / `main.ts` | 通常実行の組み立て、CLI、進捗表示、JSON保存 |

`simulation.ts`は処理段階の開始・完了を任意のコールバックで通知し、ログの形式や保存先は知りません。モデルクライアントもイベントを通知するだけで、`run.ts`が作ったログへ接続します。[実行ログの読み方](runtime-logging.md)に保存形式と監視方法をまとめています。

`simulation.ts`以下はモデルの実接続やファイル保存を行いません。`run.ts`がクライアントを作って渡します。テストは固定回答、比較実験は対象の行動選択だけを置き換えた関数を渡します。本体は介入日時・実験ID・比較元の情報を持ちません。

行動名と引数の並びは`actions.ts`の`ACTION_FIELDS`で定義し、解析・文字列化・計画の選択肢へ利用します。人物・事実・証拠の実行時の定義は`cast.ts`を編集し、[シナリオ一覧](scenario.md)はそこから生成します。

## 1日の順序

1. 日を進め、各陣営の計画を作る。
2. 各ターンで全人物の選択を収集し、人物順に支持を更新する。支持が変わった人物は新しい立場で行動を選び直す。
3. 最終的な行動から依頼の実行を判定する。反応の問い合わせを並列で行い、全回答が揃ってから人物順に適用する。目撃はその後に記録する。
4. 王の候補評価を更新し、期限を迎えた依頼・脅しを整理する。
5. 王以外の人物が個人の整理を行う。回答を揃えてから順に信念・報告・翌日の方針へ反映する。
6. 日末のスナップショットを保存する。最終日は、その後に王が後継者を指名する。

反応の問い合わせは支持の更新・選び直し後の共通の状態から行います。通信の完了順で適用順は変わりません。結果の適用は同じ世界に順次行うため、同じ証拠に対する競合は適用時にも確認します。全操作のトランザクションや失敗時の巻き戻しは実装していません。

依頼・計画・個人の方針は選択の材料です。引き受けた依頼があっても待機を選べます。依頼の期限は翌日末までです。

## 実行結果と互換性

`World`の人物・イベント・スナップショットなどのJSON形式を維持しています。以前のログにある追加の介入メタデータもviewerの読み込みを妨げません。新しい比較実験の条件と比較元は`out/experiments/`に別途保存し、結果の世界は通常と同じ`out/runs/`に保存します。

## キャッシュと再現性

クライアントごとにメモリキャッシュと統計を持ちます。Jevはモデル・説明文・質問をキーにし、同時に届いた同一入力の問い合わせも共有します。汎用LLMはモデル・プロンプト・スキーマ・推論設定をキーにし、読み出した回答もスキーマで検証します。スキーマの版番号を手動で更新する必要はありません。

同じ回答、入力、乱数の種、適用順なら再現できます。キャッシュにない問い合わせは外部モデルが回答するため、独立した実行の完全一致は保証しません。今回、汎用LLMのキーにスキーマ自体を含めたので、旧形式のLLMキャッシュはヒットしません。次の実モデル実行では計画・個人の整理を再取得します。Jevのキャッシュキーは維持しています。
