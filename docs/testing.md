# 検証方法

## 自動テスト

`pnpm test`はNode標準のテストランナーで実行します。外部API、`.env`、保存済みの実行ログは使いません。固定回答は`tests/fixtures/`に置き、本体には含めません。

主に以下を確認します。

- 世界とスナップショットの独立性、人物ごとの情報の範囲
- 行動の形式、許可条件、依頼を実行しない選択
- 証拠、脅し、暴露、支持変更後の選び直し
- 並列問い合わせの完了順に依存しない適用結果、日末処理、最終指名
- キャッシュの保存・分離、同一問い合わせの共有、Jevの同時実行上限
- 実行ログの通常完了・失敗・SIGTERM中断、Jev/LLMの再試行の記録、機密情報を含む本文の除外、端末出力の抑制
- 計画・個人の整理の検証、比較実験、依存方向と循環依存の禁止

`pnpm verify`で型検査・テスト・生成資料の整合・viewerの描画・ビルドをまとめて確認します。型検査とテストは別の役割です。Nodeの型除去だけでは型検査されません。

## 比較実験

通常実行との違いは、一つの判断時点で行動または支持を置き換えることです。`day`・`turn`・`actor`を明示します。対象ターンで支持が変わった場合は、通常と同じく行動を選び直します。同じ判断時点に行動の指定もあれば、選び直し後もその指定を採用します。次のターン以降には適用しません。

```sh
pnpm fork --day 3 --turn 1 --actor lysander --action tell:godfrey:f_courtship
pnpm fork --day 3 --turn 2 --actor anselm --support theodric
```

`experiments/fork.ts`が通常実行と介入実行を順に回して比較します。これはプレイヤー操作ではありません。介入は反実仮想の実験なので、通常の行動候補に含まれることまでは要求しませんが、行動形式と参照する人物・事実・証拠は検証します。通常なら起きない条件を与えた場合、その結果として解釈してください。

実験条件は`out/experiments/`、世界の実行結果は`out/runs/`に保存します。旧CLIの省略可能だった`--turn`は必須です。

## 実モデルの評価

`experiments/evaluations/`はAPIを呼ぶ観察用プログラムです。自動テストとは別に実行します。

| 入口 | 用途 |
| --- | --- |
| `pnpm smoke` | Jevへの基本的な問い合わせ |
| `pnpm sensitivity` | 入力変更に対する判断の変化 |
| `pnpm checks` | 判断傾向と保存ログの指標の表示 |
| `experiments/evaluations/determinism.ts` | 同一入力に対する実モデルの揺れ |
| `experiments/evaluations/latency.ts` / `effort.ts` | 待ち時間・推論設定の調査 |
| `experiments/evidence-scenario.ts` / `threat-scenario.ts` | 指定した行動から数日間の変化を観察 |

直接実行する場合は`node --experimental-strip-types --env-file=.env <path>`を使います。`checks`の✓/✗は観察指標で、テストの終了コードではありません。評価結果の妥当性は人が確認します。

## 保存ログの分析

`scripts/analysis/`には、行動の内訳、計画、証拠、脅しなどを読むツールを置いています。一部は過去の調査条件や実行ファイルを前提にしています。新しいログを指定するときは各スクリプトの引数・冒頭を確認してください。これらを自動テストの合否判定には使いません。

viewerは`pnpm viewer:smoke <run.json>`で過去のログも描画できます。引数なしでは固定回答から生成した世界を使います。
